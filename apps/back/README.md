# 木风同学的投资小站

木风同学的投资小站后端服务

服务器共享测试库已配置，本地使用 `pnpm start:test-db` 启动后端。连接配置、数据刷新和暂停方式见 [共享测试库说明](ops/test-db/README.md)。

## 数据同步

- 每天北京时间 **20:30** 检查并导入当天及此前缺失的交易日；周末、节假日只补已有交易日，不导入休市日期。
- 应用启动后在后台执行同样的检查。启动时间早于 20:30 时，最晚只处理前一天，避免导入未发布的当日行情。
- 自动任务默认只在生产环境启用。`SYNC_SCHEDULE_ENABLED` 和 `SYNC_ON_STARTUP` 可分别控制定时同步与启动补同步；测试库配置均为 `false`。
- 手动 `POST /daily-task/import`（`date`）及 `POST /daily-task/bulk-import`（`startDate`、`endDate`）保持原路径和参数；需要加环境配置中的全局 API 前缀。
- 每日快照先拉取、校验，再在一个事务内替换日线、涨跌停与情绪指标；重复导入不会累加重复记录。修正某日数据后会同时重算已有的下一交易日情绪指标。
- 基础表同样先拉取后事务替换。空快照或条数比原数据减少超过 20% 时拒绝替换并记录错误。游资名录失败保留旧值，不阻断行情。
- 网络超时、服务端临时故障和短期限流最多尝试 3 次，间隔 1 秒、2 秒；权限、积分及日配额错误不自动重试。
- 同一数据库的导入、批量导入和删除使用 MySQL 命名锁互斥；手动操作遇到正在运行的任务返回冲突，自动检查则跳过本轮。

### 任务状态和补同步范围

`t_sync_run` 保存任务日期、状态、尝试次数、各表条数和错误原因。`daily` 为行情任务，`active-funds` 为游资任务，`scope` 保存自动补同步的起点。

- `success`：行情与情绪指标均已完成。
- `pending`：行情已保存，前一交易日的数据不足，等待情绪指标补算；不会写入伪造的零值指标。
- `failed`：本次失败，已提交的旧数据保持不变，下次检查重试。
- `running`：正在运行；进程意外退出留下的状态也会在下次检查重试。

首次自动检查以现有日线最早日期为起点；空库以最近一个可同步的交易日为起点。已有完整历史数据保持使用，不会全量重新抓取。自动检查通过各表条数及任务状态识别缺口。计算情绪指标需要时，会额外导入前一个交易日作为依赖；无法获取时保持 `pending`。

可选环境变量：

| 变量 | 默认行为 |
| --- | --- |
| `SYNC_START_DATE` | 可显式设置起点，如 `2024-01-01`；未设置时使用上述规则并持久保存起点 |
| `SYNC_MAX_DAYS_PER_RUN` | 每轮最多选择 30 个缺失日期，包含最新交易日，剩余缺口下一轮继续；必要的前置交易日另行补入 |

手动删除日期后，该日期成为缺口，下一轮自动检查会重新补齐；相关的下一交易日情绪指标也会先失效再补算。清空功能会同时清理任务状态。

### 升级数据库（先迁移，再启动新版服务）

生产环境继续使用 `DB_SYNCHRONIZE=false`。开发环境已有数据时也必须先完成下面的迁移，避免自动建唯一索引因历史重复行失败。

1. 停止旧后端实例，备份业务数据库。迁移会扫描历史表并创建唯一索引，应在维护窗口执行。
2. 在 `apps/back` 目录运行 `pnpm build`。迁移使用编译产物，因此生产镜像无需安装开发依赖。
3. 确认 `NODE_ENV` 与 `DB_*` 环境变量指向目标库，运行 `pnpm migration:show`、`pnpm migration:run`。迁移入口默认读取 `.env.production`，开发库需显式设置 `NODE_ENV=development`。
4. 启动新版后端，检查同步日志及 `t_sync_run`。迁移不会随服务启动自动执行。

迁移给日线增加「代码 + 日期」、涨跌停增加「代码 + 日期 + 类型」、情绪指标增加「日期」唯一约束。同一业务键保留 ID 最大的一行；被删除的重复行会先保存到对应的 `*_sync_backup_20260926` 表。迁移可重跑，不覆盖原备份。`pnpm migration:revert` 只移除这些唯一索引，保留任务表和备份表；恢复旧数据需按备份人工核对，避免覆盖后续更新。

### 验证

`pnpm test --runInBand` 运行单元测试。MySQL 事务和迁移集成测试默认跳过；设置 `SYNC_TEST_MYSQL_PORT` 后会仅连接 `127.0.0.1` 上的独立测试实例（root，密码由可选的 `SYNC_TEST_MYSQL_PASSWORD` 指定），创建并清理一个 `stock_sync_test_*` 临时数据库，完全不读取业务 `DB_*` 配置。
