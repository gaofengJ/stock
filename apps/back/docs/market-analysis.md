# 市场分析实施与运行

本次包含大盘概览 `/analysis/overview`、市场情绪 `/analysis/senti`、涨停复盘 `/analysis/limits`、连板分析 `/analysis/chains`。旧权限代码、旧接口和六种策略保持兼容；新增 `analysis:overview` 权限，迁移授予内置 admin/user 角色，自定义角色可在权限管理中分配。

## 数据与口径

新增表：`t_source_index_daily`（8个指数日线）、`t_processed_market_daily`（交易日×6种范围 JSON 汇总）、`t_source_bse_mapping`（北交所新旧代码）。个股日线、每日指标、涨跌停价格合并到现有日线表；涨跌停事件复用原表。主页面只读本地数据，不随访问调用 Tushare。

范围为沪深京全部、沪深、主板、创业板、科创板、北交所。主板含沪深主板，北交所单列。日线成交额由千元除以100000转亿元；涨跌停详情金额由元除以100000000转亿元。指数成交额不参与全市场加总。涨跌家数包含 ST，仅统计有成交股票；涨跌停事件沿用数据源非 ST 口径。

触板股票按代码去重；同一日同时出现在 U/Z 的股票计入收盘封板。昨日涨停表现以昨日非一字板、非 ST/N/C/退市整理股票为样本，当日无成交或缺有效昨收价者不参与。晋级按同一股票昨日 N 板与今日 N+1 板匹配，北交所映射衔接换码。晋级分母包含昨日全部对应梯队；停牌在去向表单列。分母为0的比例返回 null，前端显示“—”。

龙虎榜仅由后端按需查询 `top_list` 和 `top_inst`，不落历史表；不同原因分组展示，不跨原因或买卖榜累计。缓存上限100项/10MiB，成功15分钟、空结果1分钟、失败不缓存，并发最多4个详情请求。Token不进入前端。

## 上线顺序

1. 按仓库现有发布流程备份、构建后端，在目标环境执行迁移预检和迁移；新增迁移为 `MarketAnalysis1790553600000`。不要启用 TypeORM synchronize。迁移幂等，回退不删除三张行情表。
2. 部署后端和前端静态导出。发布验证成功后自动提交持久化两年补齐任务。共享测试库使用新版按业务键合并的两年刷新，先复用生产原始数据，再计算缺失汇总；不能继续使用旧版30日整表覆盖。
3. 自动启动恢复由 `SCHEDULE_ENABLED`、`SYNC_ON_STARTUP` 控制；定时入口由 `SYNC_SCHEDULE_ENABLED` 控制；持久化补数执行器由 `ADMIN_JOBS_ENABLED` 控制。要连续补数，不能关闭后台执行器。开发环境不会默认启动定时拉取。
4. 在后台“数据同步”查看阶段与进度，也可提交“补齐缺失”任务。区间最多两个自然年；强制刷新会重新下载选定日期，主动删除保护不会被后台任务解除，需沿用原数据维护的显式导入流程恢复。

正式库通过现有发布脚本完成备份、迁移、接口检查和任务提交；具体完成进度以后台任务及阶段状态为准。历史原始数据已完整的日期只计算汇总，不重复请求日线。

## 任务执行

所有时间入口仍为 `DailySourceTask → DailyTaskService`，后台使用既有 `JobsService` 和数据库写锁。每日20:30启动；20:45、21:00、21:15、21:30、21:45重试；22:00刷新核对；次日07:30再核对。启动恢复不受晚间窗口限制。

基础资料刷新后，最近应更新交易日优先，再按日期升序补历史；每批最多3个交易日，批次释放写锁，执行器每5秒取下一批。网络请求不放在数据库事务中，按日短事务提交原始数据；指数逐个提交，失败后复用已成功指数。只有原始行情、前日依赖、8个指数及6个范围汇总全部满足条件才发布可用日期。

`t_sync_run` 按 task+trade_date 保存 daily、market-index、market 阶段；空事件日通过 daily 成功计数证明已采集。`t_admin_job` 保存区间、模式、状态及 completed_dates；重启将 running 恢复 queued，继续处理。临时失败任务5分钟后重试；永久权限/积分/日配额错误暂停，自动入口当日不重复请求失败阶段，次日可重查；人工重新提交后仍遵守当天暂停以避免无效调用。

两年范围以最近应有盘后数据的交易日向前两个自然年计算，额外获取首日所需前一交易日。已有完整原始行情复用，汇总缺失只计算；此前更早记录不清理。整个交易所缺失、重复键、字段异常、日期越界以及截断/重复分页都会阻止完成。没有上游最终发布标记，22:00/次晨复核仍可能收到修订。

原始数据修订撤销当日及下一交易日汇总的可用状态，后续同一流程重算。修订或前置日保护造成的失败保留原因；历史失败不阻止已完整的当天发布。游资资料失败独立记录，不作为市场分析完成条件。

## 验证

后端 `pnpm --filter back build`；单元测试 `pnpm --filter back exec jest --runInBand`。完整 MySQL 集成测试需显式设置 `SYNC_TEST_MYSQL_PORT`（可另设密码），只连接127.0.0.1，创建并清理 `stock_sync_test_*`、`stock_market_test_*` 独立库，不读取应用数据库配置。

前端 `pnpm --filter front build`，导出检查包含四个市场分析路由。运行中的 Next dev 会占用 `.next`，此时在独立的源代码副本构建，避免干扰开发服务。
