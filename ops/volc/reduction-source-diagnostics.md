# 减持公告正文抓取诊断

后台日志搜索 `reduction_plans`，区分风险查询 HTTP 错误与公告来源刷新错误。

- `request-failed`：目录/正文、公告编号、页码、尝试次数、错误码、HTTP 状态、是否复用连接、TLS 是否建立。
- `complete` / `failed`：本批正文请求数、缓存命中数、请求失败次数、缓存写入失败次数、总耗时；成功时还包含结果条数。
- `cache-write-deferred`：原文已核验，但持久化暂未完成。内存原文继续保留，下次扫描重试保存。

日志不包含原始 Axios 错误对象、请求头、认证信息或公告正文。单次连接重置不足以判断是来源服务还是网络中间环节；应结合失败阶段、公告编号及批次统计判断。

已核验的固定公告编号与发布日期对应的原文归档保留 180 天，内存仍限制 32 MiB / 5,000 篇。此缓存仅保存公告原文，不缓存“减持进行中”的判断。目录、后续实施完毕或终止公告仍按每批刷新重新检查，并按当前日期重新计算计划状态。新增公告使用独立编号读取；不以正文缓存代替最新目录检查。完整来源故障时保留上次成功快照与时间，并保留缺失警告。

正文首次请求、分页和重试共用每秒一次的启动间隔，并发上限仍为 2。连接重置或断管后使用新连接重试，最多 3 次；不对永久 HTTP 错误反复重试。正文入库遇到同步写锁冲突最多尝试 3 次，仍失败时留待后续扫描补存。
