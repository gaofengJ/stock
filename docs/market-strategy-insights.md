# 市场与策略观察

## 页面入口与口径

- 大盘概览：新高／新低家数和占比，跟随本页交易日、统计范围，支持 20／60 日和名单查看。以复权收盘价严格突破此前 N 个交易日收盘价高低为准；相等不算突破。分母是当日有成交且历史完整的股票，包含 ST，历史不足不按零计。
- 策略选股 → 横向比较：对当前候选股比较 20／60 日涨幅、全市场 RPS 百分位、同花顺行业超额涨幅、多策略交集及人气排名。行业超额单位为百分点，行业成分基准日期可查看；行业归属不唯一或价格不足时留空。
- 策略选股 → 信号后续表现：按各策略标准参数统计近 20／60 个交易日信号，观察信号日复权收盘至后 1／3／5／10 个交易日复权收盘的涨跌。展示均值、中位数、上涨占比、有效样本、未到期和数据不足数量。同股不同日期分别计样本，不含交易成本，不等于可成交的策略回测收益。不跟随自定义参数。行业／题材筛选只使用信号日已存在的成分快照；没有历史成分则该日不纳入统计。
- 市场情绪 → 全市场人气榜：全市场热股日终 Top100，与上一交易日比较名次，提供上升／下降、新上榜／离榜及近 20 日排名趋势。仅跟随交易日期，隐藏市场范围筛选。策略选股保留榜单跳转及候选股名次、趋势入口。仅使用日终记录；缺榜不以更早日期代替。接口不足 100 条时展示实际条数，只比较已知名次，不把缺位判为新上榜或离榜。

## 策略页面交互与查询优化（2026-10-05）

策略间共享日期、行业／题材，各策略参数独立记忆。候选、比较和历史表现共享范围，比较周期与历史观察周期各自保留。历史表现使用标准参数，默认观察后5个交易日，突出均值、中位数、上涨比例和有效信号数；明细默认仅显示当前周期有效样本。完整规则置于抽屉，公共条件不再使用悬浮 tips。

候选首屏不再计算板块榜单，板块背景仅在启用展示列后请求。传统形态先按必要价格条件缩小日线读取范围，再投影候选相关历史身份，最终仍由原有策略规则判定。少量候选只读取其行业／题材匹配标记，避免传输全市场成分；成分缓存沿用30秒时效。保留行情发布、主动删除保护、历史名称、别名冲突和候选缓存版本校验。

横向比较按候选代码返回；只读取前后两个交易日的人气记录，个股20日趋势点击后加载。新增只读接口使用 GET，前端按200只拆分请求、最多3批并发，兼容游客权限并限制URL长度。切换到历史表现时不再发起候选请求，搜索候选只在前端过滤。

只读服务基准使用 `apps/back/scripts/profile-strategy.cjs`，默认连接 `.env.server-test`；可通过 `APP_ENV_FILE` 明确选择已有配置。脚本使用单连接只读事务，不启动应用、调度或行情抓取。运行 `node scripts/profile-strategy.cjs 2026-09-30 gapThreeUp` 输出冷／热耗时，追加 `--verify` 对照6种形态策略及板块归属。

本次同日期、同4只候选的远程库实测：优化前冷请求38.323秒、33次查询，优化后5.170秒、13次查询；热请求从0.466秒降到0.085秒。计时含数据库往返和服务处理，不含浏览器渲染，受网络与数据库缓存影响；不代表所有策略的延迟。6种形态在2026-09-30的名单和行业／题材归属均与原实现一致。共享测试库缺少股票历史表，完整对照使用已有开发配置下的只读连接。

### 上线反馈修正

候选页使用 `includeLabels=false` 先获取股票和价格，再通过 `candidate-labels` 补行业／题材；风险资料也在名单返回后加载。后台将可索引的必要形态条件下推到日线查询，历史身份先读取代码位置，再一次提取匹配对象。候选缓存保留30分钟，每次请求仍核对源数据、身份、代码映射及删除保护版本；同一页面切换观察视图不重复筛选。

2026-09-30 gapThreeUp的4只候选，后续独立只读复测主体冷请求0.631秒、热请求0.128秒；标签另行加载。使用 `--core` 测量名单主体，`--verify` 对照原规则和板块归属。耗时为远程数据库与服务处理时间，生产负载和网络会影响结果。

加载名单和历史表现时显示独立占位，不覆盖旧行、空值指标和空表；四行周期概览使用自然高度表格，内容区统一16px间距。历史表现仅投影策略命中及后续观察日需要的个股对象，保持快照版本一致。已发布有效快照中的无成交与真正的数据不足分开列示；停牌／无成交不触发数据缺失警告，不顺延观察日期，也不按零收益统计。`--details` 可核对真实观察结果和龙版传媒信号日行情，`PROFILE_DAYS` 指定20或60日。

个股K线数据包含逐日实际开高低收、昨收、涨幅、成交额和自由流通换手率，详情不再依赖打开它的列表行。悬停在图内左侧显示当日行情，同时显示均线数值；关闭重复的浮动tooltip和缺字段的顶部摘要。策略候选、横向比较及历史信号明细均可按当前列表顺序切换上一只／下一只，边界按钮禁用，各弹窗请求独立取消。

### 跨策略和观察页查询优化

切换上方选股策略时，下方视图回到候选列表，保留交易日期和行业。观察页在组件内保留最多12组、2分钟内的成功结果，失败和手动重试仍重新请求。

快照查询按需投影后使用 MySQL COMPRESS 传输，服务端逐日解压。复权、身份和观察快照按主键、更新时间及观察修订号复用压缩内容；每个读取器最多16 MiB、512条，30分钟过期，并合并并发读取。每次仍读取发布、删除保护和元数据版本；读取期间改变版本的快照不参与本次计算。横向比较只查询候选所属行业的三个观察端点收盘价。

三个趋势策略在标准参数下，可以使用已发布且规则、参数、行情／因子修订一致的信号名单作为预筛选。身份或代码映射在快照生成后更新、缺少快照、自定义参数时回退到全市场计算；预筛选结果仍经过原趋势规则计算形态证据，完成后再次核对信号版本。少量股票只提取对应复权元组，大范围自定义筛选继续读取完整复权窗口。

2026-09-30只读远程库对照中，放量突破69只、缩量回踩24只、五线顺上29只的完整结果（含形态证据）与全量计算一致。五线顺上全量计算51.3秒、预筛选10.9秒；独立进程首次查询11.8秒、结果缓存命中0.12秒。横向比较4只候选首次1.14秒、重复0.24秒；60日三连阳历史表现首次9.7秒（上轮27.8秒），统计结果及无成交样本不变。以上包含远程数据库传输，受网络和负载影响，不代表生产接口承诺，也不代表自定义参数具有相同冷查询耗时。

`--all --panels` 测量九种策略及横向比较／标签；`--verify-trends` 对照三个趋势策略完整结果；`--comparison` 测量固定候选的横向比较；`--details` 同时校验历史统计冷、热结果一致。基准不启动调度，不写数据库。

## 数据与运行

新增迁移 `MarketInsights1791590400000`，只创建两个表，不重建已有行情表：

| 表 | 用途 |
| --- | --- |
| `t_processed_stock_insight` | 按交易日存储复权价格、RPS、新高／新低汇总与九种标准策略信号快照 |
| `t_source_ths_hot` | 按交易日保存同花顺日终热股榜单及榜单时间 |

复用现有行情、复权因子、同花顺行业成分和行业日线。信号快照记录规则版本及参数，源行情、因子或删除策略变化后旧快照失效并重新计算。读接口不触发重计算或 Tushare 抓取。

部署及日常同步加入现有后台队列 `insights` / `hot`，默认补齐最近 60 个交易日，分批处理，每批最多 3 日；工作日晚 22:40 补录日终人气。历史日期同步不会扩大自动补齐窗口。任务遵守全站同步锁、主动删除保护和失败重试规则，状态可在管理后台查看。新高／新低需要前置 61 日复权数据；九种标准策略沿用各自的历史要求。

历史表现接口只读取必要的收盘与信号字段，并按日期、股票建立查找索引；明细使用虚拟滚动，避免一次渲染数万行。所有统计严格截止所选日期，缺失保留空值，北交所代码变更沿用已有复权衔接口径。

历史日终人气接口返回空快照时，该日保留缺口、24 小时后重试，并继续补齐其他日期。不会用盘中记录冒充日终榜单，也不会将空榜视作所有股票离榜。管理后台任务保持待补状态，直到源端返回有效日终记录。
