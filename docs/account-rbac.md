# 账户与管理后台

本实现位于从 master 创建的独立分支 `codex/account-rbac`。不包含另一工作区尚未提交的同步和发布改动，不执行生产迁移或发布。

## 使用规则

- 用户通过用户名、密码自行注册，默认拥有全部现有业务模块的查看权限。
- 用户名去除首尾空白并转小写，3–32 位，字母开头；密码为 10–128 位。无短信、邮箱、邀请码或付费认证服务。
- 初始化管理员为 `mufeng`，迁移材料仅包含本次约定密码的随机盐 Argon2id 哈希。公共注册不能占用该用户名，重启或重复迁移不重置其密码。
- 管理后台包含用户管理、角色管理、同步任务和日志分析；入口随权限显示。
- 多角色权限取并集。普通用户角色仅允许配置业务查看权限；自定义角色可组合操作权限。系统管理员角色不可编辑，最后一个有效管理员不能被禁用或降级。
- 管理员重置或创建账户后，用户下次登录必须修改临时密码。用户主动改密需要原密码；改密、重置及禁用都会撤销该用户全部会话。
- 微信只预留 `t_user_identity` 和 Provider 接口，没有回调接口或登录按钮。独立博客仍公开，主站博客入口受 `blog:read` 控制。

## 安全边界

Session 令牌由 32 字节随机数产生，MySQL 仅存 SHA-256 摘要。Cookie 为 HttpOnly、SameSite=Lax；生产环境 Secure，网站必须使用 HTTPS 和同源 `/api` 代理。默认空闲 24 小时失效、最长 7 天；退出撤销当前会话。

先请求 `GET /api/auth/csrf` 获取与匿名/登录会话绑定的令牌，所有写请求发送 `X-CSRF-Token`。登录后轮换会话及 CSRF 令牌。来源不在允许列表的写请求被拒绝；不再伪造 Origin。CSRF 接口不赋予登录权限。

后端全局 Guard 对未声明权限的处理器默认拒绝。认证接口显式公共，个人接口显式只需登录；业务及管理接口声明权限目录中的编码。每次请求重新读取账号状态和角色权限。前端从 `auth/me` 的同一目录生成可见菜单及路由校验；服务端是最终权限边界。

旧用户、角色、权限 CRUD 和旧同步、日志控制器已撤下。行情写接口要求 `data:write`，并使用与同步相同的数据库锁；生产环境禁止通过通用 DELETE 接口删除行情。原有业务查询响应格式保留。共享交易日历允许实际消费它的分析、策略、行情模块调用。

登录/注册分别按 IP 限流，登录额外按账号限流；原有通用接口限流继续生效。目前应用限流为进程内实现，部署按现有单后端进程运行。扩容多实例前应在入口添加统一限流策略。

## 数据迁移

在后端目录执行：

```sh
pnpm build
pnpm migration:show
pnpm migration:run
```

数据库参数沿用现有 DB 环境变量。可用 `APP_ENV_FILE` 指定部署环境文件。迁移运行器不输出 SQL 参数、密码哈希或数据库异常对象；不要用会强制打印 SQL 参数的 TypeORM CLI 替代它。

迁移使用显式 DDL，所有环境 `synchronize=false`。上线前备份并验证恢复路径，在维护窗口停止旧版本后端写入后运行。DDL 在 MySQL 中会自动提交；异常时不能假设整次迁移已自动回滚。处理报告的冲突后可重新执行。回退需恢复经验证的备份，不提供删除账户表的 down 操作。

迁移会：

1. 检查用户名规范化后的重复、保留用户名冲突、重复角色关联和失效外键；发现问题明确中止。
2. 保留原有账号和关联，添加稳定编码、唯一索引及关联约束。不兼容的旧密码清空并标记需管理员重置，不尝试明文认证。
3. 新建会话、第三方身份、审计、人工任务表，并初始化内置角色及权限。初始化标记与管理员创建处于同一事务。
4. 仅首次保存普通角色的默认权限，后续不覆盖管理员调整过的配置。

空库迁移能初始化完整账户部分；业务行情表仍由项目现有结构初始化流程提供。测试脚本只在明确命名的本地临时库中创建用于验证的业务表，不对生产启用自动同步。

## 同步任务与合并注意事项

`POST /api/admin/sync-jobs` 提交相同起止日期表示按日同步，不同日期表示补区间；接口立即返回任务 ID。相同日期范围的活动任务返回已有任务。用户离线后任务继续。

人工任务每 5 秒检查队列，使用 MySQL GET_LOCK 串行执行，与原有定时同步共用锁；冲突后保持排队等待。执行前重新检查提交者状态和同步权限。重启后排队任务继续，运行中任务标记中断，可人工重新提交。锁仍被其他进程持有时不会把对方的任务错误标记为中断。

任务保存执行人、日期参数、状态、阶段、开始/结束时间、已执行日期和错误摘要。最新按日数据状态位于 `t_sync_run`；详情明确区分执行结束与待补齐，不计算虚构百分比。不同任务查看同一天时，日期状态显示最新补齐结果。

当前 master 缺少另一任务正在开发的新版同步实现，因此本分支给现有同步服务增加了：

- 同一数据库范围的写锁；
- 先获取并检查数据再事务替换快照，失败保留已有快照；
- 拒绝空数据、重复数据、日期不一致及少于已有快照的数据；
- 数据源失败不再静默返回成功；
- 缺少前一交易日依赖时，情绪指标记为待补齐而不是写入假零值。

默认保守保留已有数据；数据源合法缩减记录数或空涨跌停结果，也需要人工核验后处理。本期不提供清库界面。

**与另一同步分支合并时必须核对** `DailyTaskService`、`DailySourceTask`、`t_sync_run` 结构与锁命名。不能让两个版本使用不同锁名并行写入；不要直接叠加两个不兼容的建表迁移。保留另一分支更完整的数据一致性保护后，再运行本文测试。定时调度仍为工作日 19:50（上海时区），审计身份为 system。

## 日志

日志写入和查询都使用 `LOG_DIR`，默认后端进程的 `logs` 目录。应用日志保留沿用 `LOGGER_MAX_FILES`。容器时区设为上海，使每日文件与页面日期一致；数据库时间建议配置 UTC，认证有效期和审计插入显式使用 UTC。

应用日志以流读取主文件，避免与 error 文件重复计数。默认当天，最多 7 个自然日；单行上限 1 MB，单次总扫描上限 128 MB。遇坏行跳过并计数；超限时返回 `truncated`，页面明确显示结果不完整，应缩小日期范围。分页只保留当前页数据，显示可用日志日期、等级分布及每日错误数。

审计记录登录、资料/用户/角色调整、密码重置、同步提交和结果，默认保留 90 天，每日清理。日志及审计统一脱敏认证字段；数据库日志省略参数，认证相关 SQL 整体隐藏。页面不提供任意文件路径读取。

## 部署配置与冒烟

参考 `apps/back/.env.auth.example`：

- `AUTH_ALLOWED_ORIGINS`：准确的站点来源，逗号分隔，生产必填。
- `AUTH_IDLE_HOURS=24`、`AUTH_MAX_DAYS=7`。
- `TRUST_PROXY`：只有后端仅由可信反向代理访问且转发头由代理覆盖时才设为 true。
- `LOG_DIR`：持久化挂载并确保应用进程可读写。
- `SCHEDULE_ENABLED`、`ADMIN_JOBS_ENABLED`：本地隔离验证设为 false，生产正常启用。
- `TZ=Asia/Shanghai`。

反向代理必须保留 Cookie、Set-Cookie、Origin 和 X-CSRF-Token，不缓存 API 响应。现有站点外层代理继续负责 `/api` 和公开博客。静态页面路由使用目录中的 `index.html`（例如 `try_files $uri $uri/ =404`），不能把所有路由都重写为根首页。前后端协调发布，静态文件不含受保护业务数据。

后端 Dockerfile 在生产依赖安装后运行真实的随机密码 Argon2id hash/verify 检查；本机未安装 Docker，因此这里只验证了 Windows 原生模块，Linux Alpine 镜像步骤需在支持 Docker 的环境执行。

部署主机在迁移并启动新版本后执行：

```sh
SMOKE_BASE_URL=https://your-site.example/api pnpm smoke:auth
```

脚本直接通过部署端数据库创建最长 5 分钟的管理员验证会话，检查受保护只读接口，并在 finally 中撤销。令牌不打印、不写文件；没有新增公网登录后门。进程被强制结束时会话也在 5 分钟后过期。原外部 `/home/stock-back-deploy.sh` 不在仓库中，需把此命令接入它的健康检查阶段后再发布。

测试库行情刷新必须使用显式行情表允许列表；不得复制 `t_user*`、`t_role*`、`t_permission`、`t_auth_*`、`t_admin_job`。本分支不改变其他任务维护的刷新脚本。

## 验证

从后端目录：

```sh
pnpm build
pnpm exec jest --runInBand
pnpm check:argon2
AUTH_TEST_PORT=33387 AUTH_TEST_DATABASE=stock_auth_test_run1 pnpm test:accounts
AUTH_TEST_PORT=33387 AUTH_TEST_DATABASE=stock_auth_test_legacy1 node test/migration-legacy.cjs
```

MySQL 必须是本机隔离实例。可用 AUTH_TEST_USER/PASSWORD 指定该实例凭据。集成脚本只接受 `stock_auth_test_*` 名称，要求新库，验证结束删除自己创建的库。不要指向已有生产或共享测试库。

前端执行 `pnpm --filter front build`，本地开发可设置 `API_PROXY_TARGET=http://127.0.0.1:3317` 并选择独立端口。

自动检查覆盖会话、CSRF、批量赋值防护、角色并集及权限收回、账号禁用、最后管理员保护、重置/改密撤销、迁移重复执行与旧结构、任务重复/锁冲突/中断/失败重试、日志筛选及有界读取、审计脱敏。控制器清单测试检查所有已启用业务处理器的显式权限声明。

浏览器验收使用隔离库中的临时账号；不连接真实行情源，不执行生产同步。真实 Tushare 数据完整性、生产镜像及线上反向代理仍需在发布前按部署环境复验。
