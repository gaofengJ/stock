# 游客体验与登录动态

- 首次进入平台业务页面时创建5分钟体验；登录、注册页面本身不开始计时。
- 后端在每个业务GET请求检查固定截止时间。游客仅拥有业务查询权限，不能访问个人资料、管理后台或写入接口。
- 体验使用独立的HttpOnly、SameSite=Lax Cookie，生产环境启用Secure。浏览器标识保存一年，刷新、切换页面、退出登录和服务重启不会续时。清除Cookie或更换浏览器会视为新访客；这不是匿名用户身份识别或防爬机制。
- 复用现有匿名会话表存储截止时间；过期记录被清理后，仍持有标识的浏览器继续判定为已过期。CSRF会话不能替代体验会话。
- 注册创建账户、分配普通用户角色、轮换会话及写入登录审计在同一数据库事务中完成。管理员创建用户的流程保持原样，不切换管理员会话。
- 普通用户每次成功登录以及注册后自动登录写入`auth.member-login`审计。管理员自身登录不提醒，失败登录不提醒。
- 拥有`users:manage`权限的管理员可查看登录动态。导航徽标每30秒更新；抽屉展示最近50条。沿用审计的90天保留策略。
- 新表`t_auth_activity_read`按管理员保存已读审计ID。标记已读仅推进到已展示快照的ID，不影响其他管理员，也不吞掉并发到达的新消息。
- 主站`/blog`受统一页面边界控制；独立文章静态资源地址`/blog-frame/`仍保持原有公开阅读方式。

发布顺序：先运行`LoginActivity1790640000000`迁移并部署后端，再发布前端。不修改行情表或采集任务。

验证：后端`guest.spec.ts`、`security.spec.ts`、`profile.spec.ts`，前端`node --test scripts/test-guest-access.cjs`。账户集成测试同时覆盖注册自动登录及登录动态的权限和已读游标。
