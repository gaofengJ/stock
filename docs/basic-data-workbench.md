## 数据结构与容量

- 唯一新表：t_source_basic_snapshot。按接口、参数、字段组合生成键，保存来源响应及获取/重试时间、错误状态。
- t_source_stock.act_name 由 VARCHAR(16) 扩大到 VARCHAR(512)，实测部分控制人名称达 68 字；不新建控制人表。
- 股票沿革复用 t_source_stock_history 的 JSON 快照，北交所代码复用现有映射；行情、交易日历、同花顺行业题材及游资名录复用原表。
- 不新增个股档案、财务、风险、事件、席位专用表。缺失来源不会写入伪造数据。
- 解禁来源按日分批读取，避免 30 天超过 10 万条股东记录的接口上限；事件长列表启用虚拟滚动。
- 缓存有效期 6 小时；权限/日额度失败冷却 24 小时，其他来源失败 5 分钟。单进程并发 2、起始请求间隔 400ms、待处理键最多 80。
- 每个来源响应最多 12 MiB；写入与行情同步共用互斥锁并串行排队。每天清理 120 天未更新缓存。生产 22:10 预热最近交易日风险与未来 30 天事件；SCHEDULE_ENABLED=false 禁用定时任务。
- 发布空间只估算新增缓存和股票小表变更，不重建每日行情表。

## 口径

- 公司介绍、控制人、当前状态是最新资料；观察日期不把这些冒充历史资料。
- 财务按观察日以前已披露、最新报告期选择；经营现金流与财务指标使用同一报告期且为合并报表。利润及现金流为报告期累计数。
- 同花顺成分快照晚于观察日时，档案明确提示仅作当前归属参考。
- 停复牌显示当日事件记录，不据此推断跨日连续停牌。风险源未就绪显示待核实，不表示没有风险。
- 事件为最新已知日程，预约财报可能调整；预告、快报按实际公告日展示。解禁按同股同日合并，股东/限售类型的修订公告取最新，数量为这些明细之和，不加总重复比例。
- 席位仅覆盖成功取得的交易日；不同上榜原因、买卖侧可能重复，不能跨榜加总成资金收益。游资关联来自公开名录，不是账户实控证明。
- 无需新增高积分专属游资交易接口；沿用现有名录与 top_inst 公开席位记录。

## 验证

- 个股档案按基本资料、财务分区请求，K 线与风险详情按需加载。基本资料在 MySQL 5.7 内投影该股公司与名称记录、所属板块，避免传输整市场 JSON；失败刷新不会用单股投影覆盖完整缓存。
- 日期选择写入 URL；首次加载使用骨架屏，刷新保留已取得数据，切换股票或日期取消旧请求；轮询达到上限后显示重试入口。
- `pnpm -C apps/front run test:profile` 验证日期链接、网址与轮询生命周期；后端 `profile.spec.ts` 验证分区隔离、公告边界、现金流报告期、沿革投影及缓存失败保护。
- 2026-10-05 本地只读服务抽样（600081.SH，观察日 2026-09-30）：基本资料首次 1365ms、重复 82ms，财务 359–684ms；同库原全量沿革和公司 JSON 传输分别约 18s、22s。该结果为单次开发环境样本，不代表线上时延保证。

后端测试覆盖历史公告边界、来源并发去重/失败保留、旧名旧代码查询、退市记录、解禁修订去重；MySQL 发布测试覆盖新表及实控人列扩展、迁移重复执行。前端构建检查所有静态深链接。
## 目录与行情列表查询优化（2026-10-06）

- 个股目录先读取代码、名称及筛选字段，分页后仅获取当前页的完整公司资料；历史快照只读取代码目录及当前表缺少的退市档案。名称检索投影曾用名与代码，不传输完整历史公司 JSON。
- 每日交易数据按查询需要读取北交所代码映射或曾用名，纯代码查询不读取历史名称。行情分页、全结果排序、市场范围、缺失行情与历史日期口径保持不变。
- 股票目录、名称和代码映射、按日期分开的行业题材关联在单进程内复用30秒；相同列表查询复用10秒并合并并发请求。查询失败立即移除缓存，允许重试；数据同步后的列表最多经过这些短缓存有效期可见。该查询缓存独立于来源响应的6小时缓存，不新增数据表或迁移。
- 只读开发数据库抽样：个股目录首次26.8s降至4.4s，目录名称查询24.6s降至1.4s，每日行情名称查询22.3s降至1.7s。结果为远程开发数据库的单次样本，不代表生产时延保证。
- 回归覆盖分页后完整资料、历史退市档案、北交所别名、名称投影、缓存并发去重/过期/失败重试，以及日期、范围、排序和页码隔离；发布流水线继续运行 MySQL 5.7 集成验证。
- 同一只读数据库对比19组新旧返回值完全一致，包括完整字段、退市筛选、曾用名、北交所旧代码、市场范围、板块、分页、排序和可选列；四种列表的相同查询重复读取均未执行 SQL。

## 风险资料与列表优化（2026-10-06）

- ST 状态日期、实际公告日、发生或实施日分别返回和展示；未知公告日不使用观察日补齐。保留观察日前已披露的全部状态变更，最近变更不等于当前全部触发原因。
- 分类检索返回匹配公告和财务事实，展开可查看原文链接。状态区分有待核实线索、未检索到相关线索、资料不完整；不把关键词匹配或没有匹配当成风险结论。
- 弹窗分为资料概览、分类线索、全部公告，正文高度随视口限制，标题和关闭按钮不随正文滚出屏幕；公告长标题换行，按8条分页。列表默认50条，说明保留两行并通过风险资料查看完整内容。
- 财务零值正常显示，缺少历史资料、获取中、轮询停止和获取失败分别提示；失败冷却显示下次可获取时间，“检查更新”遵循原有冷却策略。用户界面只展示资料更新时间，不展示供应商名称或内部接口名。
- 单股风险读取在 MySQL 5.7 中投影该股及旧代码的全部匹配记录，避免传输市场快照；按股票读取名称，不附带页面未使用的行业题材明细。全市场检索仍支持板块过滤，相同风险查询复用10秒，名称目录及代码映射复用30秒。
- 投影分两次查询，使用获取时间校验版本；刷新期间版本变化会重试一次，失败刷新不能覆盖全市场缓存。回归覆盖同股多条事件、旧代码、公告边界、版本变化、失败冷却、零值与分类明细。
- 开发数据库只读对比（000010.SZ，观察日2026-09-30）：风险详情旧查询47.6秒，投影查询0.6秒，风险记录种类和数量一致，财务公告边界未改变。此为远程开发环境单次样本，不代表生产时延保证。

## 当前减持期间与展示间距（2026-10-06）

- 风险列表、策略标签、涨停分析与复盘排除规则统一只使用所选日仍处于已披露起止日期之内的减持记录，起止日期均包含边界日，且公告必须已披露。已结束、尚未开始、日期不明确及已被同一股东同一起始期间的后续披露替代的记录不作为当前减持标签。
- 股东增减持数据描述已披露的变动期间，不是完整的减持计划登记。未取得期间内记录不表示没有正在执行的计划；计划公告保留为待核实线索，完成、终止及届满公告单独展示，不自动当作进行中的计划。
- 单股风险资料保留历史及期间待核实记录，显示起止日期和期间状态。全市场接口仅返回当前期间记录，避免把近180日历史变动当作当前减持。
- 同一事项在跨月缓存中重复出现时去重。每条风险记录使用包含类型、公告日、期间、来源和内容的稳定标识，筛选类型后不复用其他事项的表格行。
- 资料更新时间、说明和表格之间设置明确的行距与间距，不依赖被全局样式重置的段落默认边距。
